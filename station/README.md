# Активация ключей — веб-станция выдачи кодов

Локальный сайт для владельца «АгроПрогноз — Кукуруза»: вставили **то, что
прислал пользователь** → получили **персональный код активации**, готовое
сообщение покупателю, файл `.agrolic`, запись в журнале выдачи и **ссылку на
скачивание проверочного EXE**, который при первом открытии запросит код — даже
на том компьютере, где приложение уже активировано.

Станция работает **без интернета и без зависимостей**: нужен только Node.js
20.19+. Закрытый ключ никуда не отправляется — страница получает только
результат подписи.

```
┌───────────────────────┐   текст заявки    ┌────────────────────────────┐
│ покупатель  EXE       │ ────────────────► │ станция (127.0.0.1)         │
│ экран активации       │                   │  · разбирает код компьютера  │
│ «Отправить заявку»    │ ◄──────────────── │  · подписывает код Ed25519  │
│   вводит код          │  код + .agrolic + │  · пишет журнал выдачи      │
│                       │  ссылка на EXE    │  · готовит проверочную копию│
└───────────────────────┘                   └────────────────────────────┘
```

## 1. Создать свой репозиторий «Активация ключей»

Станция лежит в каталоге `station/`. Чтобы сделать из неё отдельный репозиторий:

```bat
cd путь\к\Weather_Cover
npm run station:export
```

Скрипт скопирует станцию в `..\agro-activation-keys` (рядом с проектом) и
напечатает готовые команды. Останется создать репозиторий на GitHub и запушить:

```bash
cd ../agro-activation-keys
git init -b main
git add -A
git commit -m "Станция выдачи кодов активации"
gh repo create agro-activation-keys --public --source=. --push --description "Активация ключей: выдача кодов и проверочных EXE для АгроПрогноз — Кукуруза"
```

Или без `gh`: создайте пустой репозиторий на сайте (имя можно
`agro-activation-keys`, а в описании — «Активация ключей»: GitHub не любит
кириллицу в URL), затем

```bat
git remote add origin https://github.com/ВАШ_ЛОГИН/agro-activation-keys.git
git push -u origin main
```

Репозиторий может быть **публичным**: в `.gitignore` не попадают `data/` (закрытый ключ
и журнал) и `out/` (проверочные копии EXE), а в `vendor/` лежит только код
проверки и формат кода — открытые ключи не секрет (они и так внутри приложения).

## 2. Запуск

```bat
npm start
```

В консоли появится ссылка вида `http://127.0.0.1:8793/?token=…`, браузер
откроется сам. Токен в ссылке — «пароль» станции на время её работы: без него
запросы к API не проходят.

Ничего устанавливать не нужно (`npm install` не требуется — зависимостей нет).

### Офлайн-версия одним файлом

`standalone/aktivaciya-klyuchey.html` — та же выдача кодов, но без сервера: файл
лежит в репозитории, его достаточно скопировать на любой компьютер и открыть
двойным щелчком (нужен свежий браузер: Chrome/Edge 137+, Firefox 130+, Safari 17+
— в них есть Ed25519 в WebCrypto).

```bat
npm run standalone       :: пересобрать файл (это делают после правок в vendor/)
npm run standalone:check :: проверить, что файл соответствует исходникам (это же в CI)
```

Что в нём есть: разбор заявки (текст письма, .agrorequest, «Код компьютера:
XXXX-XXXX»), выдача персонального и универсального кода, проверка кода, журнал и
скачивание CSV/.agrolic, ссылка на EXE и инструкция по сбросу активации.

Чего в нём нет сознательно: закрытый ключ вводится вами и хранится только в
`localStorage` этого браузера (кнопка «Забыть» на вкладке «Ключи» удаляет), на сервер ничего не
отправляется — сеть странице не нужна вовсе. Журнал тоже локальный: в общий
`data/ledger.csv` записи попадают из станции с сервером (`npm start`).

Формат кода в файл не переписан «на глаз»: он вставляется дословно из `vendor/`
(тот же `core.cjs`, что в приложении), а браузерная часть — подпись и проверка
через WebCrypto — сверяется с приложением тестами.

## 3. Что станции нужно от жизни

| Что | Откуда берётся | Если не найдено |
|---|---|---|
| Закрытый ключ лицензий | `../Weather_Cover/secrets/license-key.json`, иначе `data/license-key.json`, иначе `AGRO_LICENSE_KEY_FILE` | выдача кодов недоступна: разбирать заявки и проверять готовые коды станция при этом умеет. Создать ключ: `npm run license:keygen` в проекте приложения |
| Открытые ключи и отзывы (публичные) | `electron/license/keys.cjs` соседнего проекта, иначе `data/keys.json`, иначе `keys.json` станции | станция не сможет проверить, что код примется: укажите `AGRO_APP_KEYS_FILE` |
| Журнал выдачи | `../Weather_Cover/secrets/ledger.csv`, иначе `data/ledger.csv` (`AGRO_LEDGER_FILE`) | журнал создаётся при первой выдаче |
| EXE, из которого делать проверочную копию | `../Weather_Cover/release/AgroPrognoz-*.exe`, иначе `AGRO_EXE` / `--exe путь` | даётся ссылка `AGRO_EXE_URL` + инструкция «переименуйте файл» |

Станция сама находит проект по соседству (`../Weather_Cover`, `AGRO_REPO` или
`--repo путь`). Ничего не «звонит» наружу: запросы идут только на
`127.0.0.1`.

## 4. Выдача кода покупателю (основной путь)

1. **Вкладка «Заявка → код».** Вставьте в первое поле всё, что прислал
   пользователь: текст с экрана активации, содержимое `.agrorequest` или
   сообщение из мессенджера. Станция вытащит код компьютера (`ZZG5-9ZKT` или
   полный 64-символьный идентификатор), имя, телефон и почту — поля формы
   заполнятся сами. Принимается и «голый» код, и с опечатками `O→0`, `I/L→1`.
2. Нажмите **«Разобрать заявку»**, при необходимости поправьте поля, затем
   **«Сгенерировать код»**.
3. Получите: персональный бессрочный код, готовое сообщение покупателю, файл
   `.agrolic`, записанный в журнал серийник — и ссылку на скачивание
   проверочного EXE.
4. Отправьте покупателю код (или `.agrolic`). На другом компьютере он не
   заработает: «Код выписан для другого компьютера».

**Повторная заявка.** Если этому компьютеру код уже выдавался, станция
предупредит и покажет прежнюю запись. «Продолжить и отозвать старый» —
перевыпуск с новым серийником и отзывом прежнего (при linked-проекте серийник
добавляется в `electron/license/keys.cjs`; в следующей сборке EXE старый код не
примется).

**Универсальный код** (работает на любом компьютере) выдаётся только после
отдельного подтверждения — используйте для выставок и временных машин.

## 5. Проверочный EXE: как увидеть экран активации у себя

Приложение хранит лицензию в `%APPDATA%\AgroPrognoz\agroprognoz.license`, и файл
этот один на все копии программы. Поэтому свежескачанный EXE на активированном
компьютере код **не спросит**. Проверочная копия называется
`AgroPrognoz-check-<id>.exe` и хранит лицензию в отдельном файле
`agroprognoz-check-<id>.license` — она обязана запросить код, а ваша основная
активация и база данных остаются нетронутыми.

Станция делает такую копию из уже собранного EXE: это тот же файл, только с
другим именем (ссылка «Скачать AgroPrognoz-check-….exe» ведёт на копию из
`out/`). Режим описан в проекте приложения: `electron/license/checkmode.cjs`,
`docs/ПРОВЕРКА-АКТИВАЦИИ.md` проекта приложения.

Проверьте за один прогон:

```bat
:: в проекте приложения
npm run license:status              • есть ли активация сейчас
npm run activation:selftest         • весь механизм активации (21 проверка)
```

## 6. Отзыв, журнал, CSV

Вкладка **«Журнал»**: поиск по имени, телефону, серийнику, коду компьютера;
кнопка «Отозвать» у каждой действующей записи; «Скачать CSV» — резервная копия
учёта. Формат журнала совместим со «Студией лицензий» проекта (тот же
`secrets/ledger.csv`, колонки через `;`).

## 7. Конфигурация

Флаги `npm start -- …`:

| Флаг | Значение |
|---|---|
| `--port N` | порт (по умолчанию 8793, при занятом перебираются следующие 16) |
| `--repo путь` | где искать проект `Weather_Cover` |
| `--exe путь` | файл или каталог с EXE (несколько через `;` в Windows, `:` в Linux) |
| `--exe-url URL` | ссылка на EXE для покупателя (он переименует файл сам) |
| `--out путь` | куда класть проверочные копии |
| `--no-open` | не открывать браузер |
| `--lan` | слушать `0.0.0.0`, чтобы открыть станцию с другого компьютера той же сети (только доверенная сеть: выдача кодов — это право подписи) |
| `--allow-host домен` | разрешить дополнительные Host-заголовки (адрес туннеля, превью). Станция при этом тоже слушает `0.0.0.0`, но чужие имена по-прежнему отклоняет — защита от DNS-привязки остаётся |

Переменные окружения: `AGRO_LICENSE_KEY_FILE`, `AGRO_APP_KEYS_FILE`,
`AGRO_LEDGER_FILE`, `AGRO_REPO`, `AGRO_EXE`, `AGRO_EXE_URL`, `AGRO_STATION_OUT`,
`AGRO_STATION_PORT`, `AGRO_STATION_HOST`, `AGRO_STATION_ALLOW_HOST` (список доменов через `;`).

## 8. Как устроено и как не разъезжается с приложением

```
src/main.mjs      запуск: конфигурация, сервер, ссылка в консоли
src/server.mjs    HTTP: loopback + токен, раздача страницы и EXE
src/backend.mjs   выдача кода, проверка, журнал, отзыв, проверочные копии
src/config.mjs    где лежат ключи, журнал, EXE; как искать соседний проект
src/request.mjs   разбор заявки (текст, .agrorequest, свободное сообщение)
vendor/           ТОЧНЫЕ копии кода приложения: core.cjs (формат кода),
                  store.cjs (конверт лицензии), machine.cjs (идентификатор
                  компьютера), checkmode.cjs (проверочный режим),
                  license-shared.mjs, activation-doctor-lib.mjs,
                  guard.cjs (тексты отказов — читаются как текст, не исполняется)
keys.json         открытые ключи и отзывы (публичные) — чтобы проверять коды
.github/workflows/CI: тесты + проверка, что зависимостей нет и что закрытого
                    ключа в репозитории не появилось
tests/            station.test.mjs — разбор заявки, выдача, журнал, отзыв, EXE,
                  доступ по сети (28 проверок);
                  standalone.test.mjs — офлайн-файл: он актуально собран из
                  исходников, его вердикты совпадают с приложением, а вся
                  страница прогоняется на фиктивном DOM (41 проверка)
```

Станция подписывает коды **тем же кодом формата**, что приложение проверяет, —
`vendor/` это копии исходников проекта. После изменений в лицензировании
обновите их и проверьте:

```bat
npm run sync             :: переписать копии из соседнего проекта
npm run sync:check       :: убедиться, что копии не «подправлялись» вручную
npm run standalone       :: пересобрать офлайн-файл из этих копий
npm test
```

## 9. Частые вопросы

| Симптом | Причина и решение |
|---|---|
| «Закрытый ключ не найден» | в проекте приложения: `npm run license:keygen`, либо положите ключ в `data/license-key.json`, либо укажите `AGRO_LICENSE_KEY_FILE` |
| «Открытый ключ key-id=N не добавлен…» | код этим ключом приложение не примет: `npm run license:keygen` в проекте должен обновить `electron/license/keys.cjs`, затем пересоберите EXE |
| Проверочный EXE не спросил код | копия собрана из старой сборки без `license/checkmode.cjs` — пересоберите `npm run dist:win`; либо файл назван не по схеме `AgroPrognoz-check-<id>.exe` |
| Не нашло код компьютера | в тексте нет ни `XXXX-XXXX`, ни 64 hex-символов; попросите покупателя нажать «Скопировать заявку» и прислать файл |
| Порт занят | `npm start -- --port 9100` |
| Открываю ссылку с другого ПК — «недоверенный хост» | запускайте с `--lan` (или `--allow-host ваш-домен`) и держите токен при себе |

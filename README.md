# АгроПрогноз — Кукуруза

Настольное приложение (Electron): выбор территории на карте, настройка параметров
прогноза и просмотр погодных показателей применительно к выращиванию кукурузы.

Рабочий каркас со всеми разделами: карта с выбором точки, справочник сортов,
демонстрационный прогноз с графиками, наборы данных, архив отчётов, SQLite-база
с сохранением между запусками, сборка Windows portable EXE.

Настоящего алгоритма прогнозирования здесь нет. Вместо него — детерминированный
**демонстрационный движок** со стабильным контрактом: его можно заменить
реальными расчётами без переписывания приложения (см. «Замена демодвижка»).
Синтетические значения нигде не выдаются за реальные наблюдения: в интерфейсе,
данных и отчётах стоит отметка демонстрационного режима.

Приложение защищено **бессрочным кодом активации**: без принятого кода оно не
открывается и не отдаёт данные. Подробно — в [`docs/ЗАЩИТА.md`](docs/ЗАЩИТА.md).

## Активация

Лицензия **бессрочная**. В коде активации нет даты, проверка не читает системное
время, «срока действия» не существует ни в данных, ни в интерфейсе: перевод
часов и откат времени на лицензию не влияют.

- **Код** — `AGRO-` и 16 групп по 8 символов (подпись Ed25519, 80 байт в
  base32 Crockford). Регистр, пробелы, переносы строк и опечатки `I`/`L`/`O` не
  мешают: код можно вставить из письма целиком.
- **Проверка** — только в main process (`electron/license/guard.cjs`). Renderer
  не знает ни ключей, ни решения; после активации данные выдаются по токену
  сессии, который живёт в preload и до интерфейса не доходит. Правка интерфейса
  поэтому ничего не даёт.
- **Хранение** — `%APPDATA%/AgroPrognoz/agroprognoz.license`, шифрование
  `safeStorage` (Windows DPAPI) плюс HMAC и привязка к компьютеру: файл,
  скопированный на другую машину, не принимается. При каждом запуске сохранённая
  лицензия проверяется заново. Новый код активируется поверх старой лицензии —
  удалять файл руками не нужно.
- **Персональные коды** — «один компьютер — один код»: покупатель нажимает на
  экране активации «Отправить заявку владельцу» (открывается его Telegram /
  WhatsApp / почта с готовым текстом; запасной путь — копирование или файл
  `.agrorequest`), владелец выписывает код в «Студии лицензий», и код работает
  только на этом компьютере. После переустановки Windows покупатель
  присылает новый код компьютера — студия перевыпускает код и автоматически
  отзывает старый.
- **Выдача кодов** — «Студия лицензий» на машине владельца (офлайн, закрытый
  ключ из `secrets/license-key.json` не покидает этот компьютер):

```bash
npm run license:studio                        # студия: форма выдачи + журнал + отзыв
npm run license:keygen                        # один раз: создать закрытый ключ
npm run license:issue -- --bind ZZG5-9ZKT     # то же из командной строки
npm run license:verify -- "<код>"             # разобрать код
npm run license:revoke -- <серийник>          # отозвать лицензию
```

Проверить активацию на своём компьютере, где она уже пройдена, помогают:
portable-копия держит файл лицензии рядом с собой (новая папка → новый запрос
кода), копии `AgroPrognoz-check-<id>.exe` — ещё и со своим именем файла лицензии,
а `npm run license:reset` убирает сохранённую активацию с резервной копией, а `npm run activation:selftest`
прогоняет весь механизм целиком — 21 проверка. Веб-станция выдачи кодов со
ссылкой на скачивание такого EXE — в каталоге [`station/`](station)
(`npm run station`), подробнее — [`docs/ПРОВЕРКА-АКТИВАЦИИ.md`](docs/ПРОВЕРКА-АКТИВАЦИИ.md).

Журнал выданных кодов — `secrets/ledger.csv` (даты — только для учёта выдачи).
Необязательный модуль доставки (СМС SMS.ru/SMSC.ru, Telegram-бот, SMTP)
включается переменными окружения и работает только из студии. Инструкция —
[`docs/ВЛАДЕЛЬЦУ.md`](docs/ВЛАДЕЛЬЦУ.md), модель угроз —
[`docs/ЗАЩИТА.md`](docs/ЗАЩИТА.md).

## Быстрый старт

Требуется Node.js 20+ и npm. Платные сервисы не нужны.

```bash
npm install          # зависимости
npm run prepare:assets  # иконки Lucide + геоданные (есть офлайн-фолбэк)
npm run icon         # иконка приложения: SVG → PNG → ICO
npm run dev          # dev-сервер Vite + браузерный предпросмотр
```

Откройте адрес из консоли (по умолчанию <http://localhost:5173>).
Порт меняется через `AGRO_PORT=5199 npm run dev`.

Запуск в Electron (нужен скачанный бинарник Electron):

```bash
# Терминал 1 — dev-сервер для Electron:
AGRO_PORT=5173 npm run dev
# Терминал 2 — приложение:
AGRO_DEV_SERVER=http://localhost:5173 npm start
```

Production-режим Electron: `npm run build`, затем `npm start`
(окно открывается через внутренний протокол `app://`, dev-сервер не нужен).

В dev-режиме (браузер или `AGRO_DEV_SERVER=…`) лицензия не требуется — иначе
разработка была бы невозможна. В собранном `AgroPrognoz.exe` первый запуск
показывает экран активации; код выписывает владелец
(`npm run license:issue -- --count 1`). Посмотреть экран активации в браузере
можно по адресу `http://localhost:5173/?license=demo` (в production-сборке этот
адрес ничего не делает — ветка вырезана вместе с условием разработки).
Системной строки заголовка у окна нет: поверх интерфейса рисуются только
кнопки окна на прозрачном фоне (`titleBarOverlay`; над картой значки светлые,
на остальных разделах тёмные), перетаскивание — за верхнюю полосу и блок
с названием в боковой панели; в браузере высота этой полосы равна нулю.

## Разделы приложения

- **Карта** — Leaflet, спутниковая подложка Esri World Imagery одной
  копией мира (без повторов по горизонтали, минимальный масштаб подбирается
  под размер окна, максимальный — 18-й уровень). Тайлы запрашиваются с
  `blankTile=false`: там, где снимка нужного масштаба нет, сервер отвечает
  404 вместо заглушки «Map data not yet available», и слой показывает
  увеличенный фрагмент снимка более мелкого масштаба. Клик выбирает точку,
  панель справа задаёт сорт, период (1/3/6 мес.) и начало периода.
- **Результаты прогноза** — показатели за период, графики температуры
  и осадков / таблица дневных значений, панель рисков, сохранение отчёта.
- **Данные** — наборы, сформированные движком: поиск, фильтр периода,
  карточка набора, сортировка, пагинация по 50 строк, экспорт CSV.
- **Отчёты** — архив снимков: поиск, фильтр сорта, порядок. Открытие
  не вызывает движок и не зависит от набора и сорта.
- **Сорта кукурузы** — справочник: название, тип (сорт/гибрид), оригинатор,
  ФАО, вегетация, примечания. Добавление, редактирование, удаление.

Новая база содержит одну помеченную запись «Демонстрационный сорт»
для проверки интерфейса. Она создаётся только при инициализации новой базы,
а не после каждого удаления всех сортов.

## Замена демодвижка

Весь алгоритм — один файл без зависимостей от DOM/Electron/Leaflet/Chart.js:

```text
calculations/forecast_engine.js  →  export async function generateForecast(request)
calculations/date-period.js      →  календарная арифметика (общая для движка и UI)
```

Приложение импортирует движок только через `ENGINE_LOADER` в
`src/services/forecast-service.js`. Чтобы подключить реальные расчёты:

1. Реализуйте `generateForecast(request)` с тем же контрактом
   (запрос `{lat, lon, varietyId, varietyName, rangeMonths, targetDate}`,
   результат `schemaVersion`/`period`/`series`/`indicators`/`risks`/`provenance`).
2. Обновите `engineVersion` и `provenance.source`.
3. Проверьте `npm test` и smoke-тест.

Календарная арифметика (`computePeriod`, високосный год, концы месяцев)
покрыта тестами и переиспользуется интерфейсом — менять её не нужно.

## База данных

SQLite через sql.js, единый интерфейс `src/services/persistence.js`:

- Electron: `app.getPath("userData")/agroprognoz.sqlite`, запись через узкий
  preload API (`window.agro`), атомарно (временный файл + замена),
  операции сериализуются, успех показывается только после записи на диск.
- Браузер: бинарный экспорт SQLite в IndexedDB.

Таблицы: `schema_migrations`, `varieties`, `datasets`, `dataset_rows`,
`reports`, `app_settings`. Запросы параметризованы, связанные операции —
в транзакциях, внешние ключи включены, миграции версионированы.
Повреждённая база не сбрасывается молча: исходный файл сохраняется,
пользователь видит понятную ошибку и может сохранить копию.

## Источники геоданных и атрибуция

Карта показывает только спутниковые снимки — контуры стран и регионов на неё
не выводятся. Геоданные ниже остаются в репозитории как подготовленные
источники (скрипт `npm run prepare:assets`, версии фиксируются
в `src/assets/geo/manifest.json`):

- **Страны мира** — пакет `world-atlas@2.0.2`, файл `countries-110m.json`
  (TopoJSON на основе Natural Earth 1:110m). Лицензии: ISC (обёртка) +
  Natural Earth public domain (данные).
- **Регионы России** — Natural Earth 1:10m admin 1
  (`ne_10m_admin_1_states_provinces.geojson`, репозиторий
  `nvkelso/natural-earth-vector`, blob SHA `4a8438f98ac7dfec7dc1739b1eaf91398ad33f22`),
  фильтр `adm0_a3 = RUS`, упрощение Дугласа–Пекера 0,004°.
  Natural Earth — public domain
  (<https://www.naturalearthdata.com/about/terms-of-use/>).

Количество и состав регионов определяются этим источником и зафиксированы
в манифесте — приложение не заявляет их как собственную справочную норму.
Границы схематичны (обзорный масштаб) и не предназначены для юридических
или кадастровых задач.

- **Подложка «Карта»** — CARTO Positron, данные © OpenStreetMap contributors
  (ODbL), © CARTO (<https://carto.com/attribution>).
- **Подложка «Спутник»** — Esri World Imagery
  (<https://www.esri.com/legal/licensing>).
- Атрибуция обоих источников сохранена на карте и кликабельна.
- **Иконки интерфейса** — Lucide (`lucide-static@1.44.0`, ISC), один набор
  контурных SVG, копия в `src/assets/icons/`. Логотип приложения нарисован
  отдельно и не является иконкой Lucide.
- **Шрифт** — Inter (`@fontsource/inter@5.3.0`, OFL), локально из npm.

## Безопасность Electron

`contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`.
Production отдаётся привилегированным протоколом `app://` с CSP-заголовком
(разрешены только собственные ресурсы и два хоста тайлов). Произвольная
навигация запрещена, внешние ссылки открываются только из allowlist
атрибуции. Preload отдаёт только операции хранения/экспорта и активации, каждая
с проверкой аргументов. Разрешения (геолокация, камера, уведомления)
отклоняются; исключение — буфер обмена для экрана активации.

ASAR — упаковка, а не защита исходников, поэтому поверх неё:

- **Electron Fuses** (`build.electronFuses` в `package.json`): `RunAsNode`,
  `NODE_OPTIONS` и `--inspect` выключены в самом бинарнике, код грузится только
  из `app.asar` (`onlyLoadAppFromAsar`), `file://` без лишних привилегий;
- **обфускация** main process: в сборку уходит `hardened/electron/`, а не
  исходники (`scripts/harden.mjs`);
- **проверка целостности** файлов сборки по SHA-256 с корневыми хэшами
  манифеста внутри обфусцированного `guard.cjs`
  (`electron/license/integrity.cjs`);
- **условия запуска**: отладчик, отладочные переключатели, переменные
  разработки и запуск не из упаковки — отказ (`electron/license/shield.cjs`);
- **токен сессии** для всех каналов данных: без активации main process не
  отдаёт ни байта, а правка интерфейса ничего не меняет.

Fuse `enableEmbeddedAsarIntegrityValidation` намеренно не включён: на Windows он
требует вшить в EXE ресурс `Integrity/ElectronAsar`, чего electron-builder не
делает, — без него приложение не запустится вовсе. Подробности и что усилит
защиту дальше — в [`docs/ЗАЩИТА.md`](docs/ЗАЩИТА.md).

## Проверено

- `npm test` — 179 unit-тестов проходят (периоды календаря, високосный год,
  валидация, детерминированность движка, границы значений, CRUD сортов,
  миграции, отчёты и их сохранность после удаления сорта/набора, CSV;
  лицензия: формат кода, подпись Ed25519, отзыв, привязка к компьютеру,
  хранилище, целостность файлов, условия запуска, страж и отсутствие дат;
  студия выдачи: нормализация кода компьютера, персональный код до активации
  стражем, перевыпуск с автоотзывом, журнал, доставка на подменённых
  транспортах).
- `npm run build` — production-сборка Vite проходит; ветка «режим разработки»
  из бандла вырезана вместе с условием `import.meta.env.DEV`.
- `npm run harden` — обфускация и манифест целостности собираются, самопроверка
  (56 проверок) проходит: обфусцированные модули работают, цепочка хэшей
  сходится, порча файла и подмена манифеста ловятся, полный цикл активации
  завершается выдачей токена, обфусцированный preload грузится и отдаёт мост
  `window.agro` целиком, не раскрывая токен сессии.
- Прогон в CI (Windows): `verify` — тесты, сборка и `harden` прошли;
  `portable` — EXE собран, `verify:package` разобрал `app.asar` (состав,
  целостность 29 файлов, страж из упаковки, все 6 фьюзов).
- `npm run prepare:assets`, `npm run icon` — выполняются.
- Dev-сервер стартует без ошибок сканирования зависимостей; все модули
  проходят трансформацию Vite.
- Ревизия кода: исправлены падение старта (порядок инициализации роутера),
  присваивания в `const`, дублирование подсказок карты, клики по регионам
  вне диапазона 4–6, потеря поля «Вегетация» при редактировании сорта,
  восстановление таблиц после пустых состояний, опечатки.

## Ограничения и что не проверялось здесь

- Браузерные проверки (`npm run test:smoke`, `test:gate`, `test:activation`) в
  этой песочнице не запускались: нет браузера и заблокирована загрузка
  Playwright Chromium. Скрипты готовы, прогон и скриншоты выполняются в CI
  (Windows) и на машинах с браузером.
- Сборка `npm run dist:win` здесь не запускалась: заблокирована загрузка
  бинарника Electron. Конфигурация electron-builder (portable,
  `AgroPrognoz-<version>-portable.exe`) и её результат проверяются в CI на
  Windows шагом `npm run verify:package` — он разбирает `app.asar`, сверяет
  целостность упакованных файлов и читает фьюзы из `AgroPrognoz.exe`.
- Запуск самого EXE в CI не проверяется (Windows-EXE не запускается на
  раннере без интерфейса): активация вживую проверяется на машине владельца.
- Окно Electron и перезапуск с сохранностью файла базы вручную здесь
  не проверялись по той же причине — требуется машина с Electron/Windows.
- Разметка 1366×768 и 1920×1080 заложена в CSS (брейкпоинт 1180 px,
  контейнерные запросы), визуально подтверждается скриншотами CI.
- САТ, ГТК и риски движком не вычисляются (`null` / `notCalculated`) —
  это зафиксировано в контракте, а не упущение интерфейса.

## Структура

```text
electron/           main / preload / файловое хранилище / CSP
electron/license/   ядро лицензии, ключи, хранилище, целостность, страж, shield,
                    request.cjs (контакт владельца и текст заявки),
                    checkmode.cjs (проверочные копии AgroPrognoz-check-<id>.exe)
src/                renderer: страницы, компоненты, сервисы, стили
src/pages/activate/ экран активации (ввод кода + заявка владельцу)
calculations/       демодвижок (точка замены) + календарная арифметика
scripts/            prepare-assets, иконка и заставка, dev/preview, license-tool,
                    license-shared (общая библиотека выдачи), license-studio
                    (студия владельца), activation-doctor (диагностика и сброс
                    активации + selftest), export-station (выгрузка станции),
                    harden (обфускация + манифест),
                    verify-package (разбор сборки + анти-слив)
station/            веб-станция «Активация ключей»: разбор заявки → код → журнал →
                    ссылка на проверочный EXE (можно вынести в свой репозиторий)
docs/               ЗАЩИТА.md — модель угроз; ВЛАДЕЛЬЦУ.md — сборка и выдача кодов;
                    ПРОВЕРКА-АКТИВАЦИИ.md — как проверить активацию на своём ПК
build/              иконка (npm run icon) и заставка portable EXE (npm run splash)
hardened/           защищённая копия electron/ для упаковки (создаётся сборкой)
secrets/            закрытый ключ лицензий и журнал выданных кодов (в .gitignore)
tests/              unit-тесты + Playwright (сценарий, защита, экран активации)
.github/            CI: тесты, браузерные проверки, Windows portable EXE
```

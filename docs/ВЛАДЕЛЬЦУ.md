# Инструкция владельца: сборка EXE

Всё, что нужно сделать своими руками: собрать `AgroPrognoz.exe` и отдать его
покупателю. Код активации не нужен — приложение запускается сразу.
Технические детали защиты — в [`ЗАЩИТА.md`](ЗАЩИТА.md), конвейер сборки —
в [`СБОРКА.md`](СБОРКА.md).

---

## 1. Сборка EXE на своём компьютере (Windows)

Нужны: Windows 10/11 x64, Node.js 20.19+ (<https://nodejs.org>), интернет для
`npm ci` и для скачивания Electron (~120 МБ один раз).

```bat
cd путь\к\Weather_Cover
npm ci
npm run icon
npm run prepare:assets
npm test
npm run dist:win
npm run verify:package
```

Готовый файл: **`release\AgroPrognoz-<версия>-portable.exe`** (~94 МБ). Его и
отдавайте покупателю — установка не нужна, запускается двойным щелчком.

Что происходит внутри `dist:win`: правка заставки установщика → `harden`
(обфускация main process + 19 самопроверок) → `electron-builder` (упаковка и
Electron Fuses в бинарнике).

`verify:package` разбирает собранное приложение и обязан закончиться строкой
`✔ Пройдено проверок: NN`. Если он падает — **не отдавайте** этот EXE: значит
сборка повреждена (см. раздел 3).

Проверки `npm test` (64 unit-теста) и браузерные `test:gate` / `test:smoke`
необязательны для сборки, но полезны: первые требуют только Node, остальные —
`npx playwright install chromium`.

### Если сборка нужна прямо сейчас, а Node ставить не хочется

EXE можно получить и без своего компьютера: GitHub Actions собирает его сам
(раздел 2). Но для этого нужен доступ к репозиторию.

## 2. Публикация через GitHub (когда есть доступ к репозиторию)

CI собирает EXE сам на Windows-раннере и публикует его в Releases по тегу:

```bash
git push origin ветка-с-изменениями
gh pr merge --merge            # или кнопкой на сайте
git checkout main && git pull
git tag v0.3.0
git push origin v0.3.0
```

Через 5–10 минут файл появится по адресу:

```
https://github.com/Igorr112323/Weather_Cover/releases/download/v0.3.0/AgroPrognoz-0.3.0-portable.exe
```

CI делает три проверки: `verify` (unit-тесты + обфускация), `smoke` (браузер:
защита production-сборки и сценарий приложения) и `portable` (сборка EXE +
`verify:package` — состав `app.asar` и фьюзы **до** публикации).

Версия в `package.json` и имя тега должны совпадать: имя файла EXE берётся из
`package.json`.

## 3. Если что-то пошло не так

| Симптом | Что делать |
|---|---|
| `npm ci` падает | Node.js должен быть 20.19+; проверьте `node -v`, переустановите Node |
| `verify:package`: «кириллица в main.cjs» | сборка собрана из исходников: пересоберите `npm run dist:win` целиком, одним прогоном |
| `harden`: «нет dist/» | сначала выполните `npm run build` |
| EXE не запускается, окна нет | смотрите, не блокирует ли антивирус/SmartScreen (подписи кода нет); второй вариант — сработал shield: удалите переменные `AGRO_DEV*` и не запускайте с `--inspect` |
| Окно открылось пустым | в CI есть шаг `smoke` со скриншотами; локально — `npm run dev` и `npm run test:smoke` |

## 4. Что усилит защиту дальше (по убыванию отдачи)

1. **Подпись кода (Authenticode, ~$200–400/год).** Убирает предупреждение
   SmartScreen и позволяет включить fuse `enableEmbeddedAsarIntegrityValidation`:
   electron-builder уже вшивает ресурс `Integrity/ElectronAsar` в EXE (видно в
   логе сборки), поэтому включение — одна строка в `package.json`. Включать
   нужно вместе с проверкой на живой машине: при несовпадении хэша Electron
   завершает приложение при запуске.
2. **Bytecode (bytenode)** для `main.cjs` и `shield.cjs`: V8-байткод вместо
   JavaScript. Требует компиляции той же версией Electron и проверки на Windows.

Готовый минимум, который уже в сборке: обфускация с переименованием имён и
спрятанными строками, шесть фьюзов в бинарнике, блокировка отладчика, данные
только через main process и отказ работать вне Electron.

# Инструкция владельца: сборка EXE и выдача кодов

Всё, что нужно сделать своими руками: собрать `AgroPrognoz.exe`, активировать
его бессрочным кодом и выдавать покупателям **персональные коды** — по одному
на каждый компьютер. Технические детали защиты — в [`ЗАЩИТА.md`](ЗАЩИТА.md),
конвейер сборки — в [`СБОРКА.md`](СБОРКА.md).

---

## 1. Что у вас на руках

| Файл | Что это | Терять нельзя |
|---|---|---|
| `secrets/license-key.json` | **закрытый ключ** лицензий (key-id=1). Единственное, чем выписываются коды | ⚠️ да |
| `secrets/ledger.csv` | журнал выданных кодов: серийник → кому, когда выдан | желательно |
| `secrets/КОДЫ-АКТИВАЦИИ.txt` | пять готовых бессрочных универсальных кодов (v0.2.0) | можно перевыпустить |
| `electron/license/keys.cjs` | открытый ключ и отозванные серийники (в сборке) | нет, в репозитории |

В репозиторий `secrets/` не попадает (каталог в `.gitignore`). Закрытый ключ
не покидает ваш компьютер: студия выдачи работает офлайн, а отправка кода
покупателю — это ваше сообщение из вашего мессенджера или почты.

**Сделайте копию `secrets/license-key.json` вне компьютера сборки** (флешка,
менеджер паролей, облако с шифрованием). Без него новые коды выписать нельзя;
уже выданные продолжат работать, потому что в приложении лежит открытый ключ.

## 2. Сборка EXE на своём компьютере (Windows)

Нужны: Windows 10/11 x64, Node.js 20.19+ (<https://nodejs.org>), интернет для
`npm ci` и для скачивания Electron (~120 МБ один раз).

```bat
cd путь\к\Weather_Cover
npm ci
npm run icon
npm run prepare:assets
npm test
npm run dist:win
npm run verify:package
```

Готовый файл: **`release\AgroPrognoz-0.2.1-portable.exe`** (~94 МБ). Его и
отдавайте покупателю — установка не нужна, запускается двойным щелчком.

Что происходит внутри `dist:win`: правка заставки установщика → `harden`
(обфускация main process + манифест целостности + 58 самопроверок) →
`electron-builder` (упаковка и Electron Fuses в бинарнике).

`verify:package` разбирает собранное приложение и обязан закончиться строкой
`✔ Пройдено проверок: NN`. Если он падает — **не отдавайте** этот EXE: значит
сборка повреждена (см. раздел 9).

Проверки `npm test` (179 unit-тестов, включая студию лицензий) и браузерные
`test:gate` / `test:activation` / `test:smoke` необязательны для сборки, но
полезны: первые требуют только Node, остальные — `npx playwright install chromium`.

### Если сборка нужна прямо сейчас, а Node ставить не хочется

EXE можно получить и без своего компьютера: GitHub Actions собирает его сам
(раздел 8). Но для этого нужен доступ к репозиторию.

## 3. Первая активация и проверка защиты

1. Запустите `release\AgroPrognoz-0.2.1-portable.exe`.
2. Появится экран «Активация приложения» с кодом этого компьютера.
3. Вставьте любой код из `secrets\КОДЫ-АКТИВАЦИИ.txt` (пробелы и переносы строк
   не мешают) → «Активировать».
4. Приложение откроется; внизу боковой панели будет «Лицензия: Бессрочная».
5. Закройте и запустите снова — активация сохраняется, код больше не спрашивает.

Универсальные коды v0.2.0 продолжают работать и в версии 0.2.1 — включая тот,
которым активирован ваш компьютер. Персональные коды ничего у них не отбирают:
это два вида одного и того же бессрочного кода, просто персональный работает
на одном компьютере, а универсальный — на любом.

### Персональный код на ваш собственный компьютер

Чтобы и ваш EXE был защищён по полной схеме, выпишите код самому себе:

1. На экране активации (или кнопкой «Скопировать» рядом с кодом компьютера)
   возьмите код вашего компьютера, например `ZZG5-9ZKT`.
2. Запустите студию (следующий раздел), вставьте код в форму, имя — «Владелец».
3. «Сгенерировать код» → активируйте приложение полученным кодом.

Если ваш EXE уже активирован универсальным кодом, ничего переустанавливать не
нужно — он продолжает работать. Хотите заменить его на персональный: один раз
удалите файл `%APPDATA%\AgroPrognoz\agroprognoz.license` — приложение покажет
экран активации, и персональный код ляжет поверх. Дальше любые новые коды
вводятся на экране активации без удаления файла: приложение само заменяет
старую лицензию новой.

Быстрая проверка, что защита работает:

- скопируйте `%APPDATA%\AgroPrognoz\agroprognoz.license` на другой компьютер и
  подложите там в тот же каталог — приложение попросит код заново;
- запустите EXE с `--inspect` или с `ELECTRON_RUN_AS_NODE=1` — ничего не
  выйдет (фьюзы выключены в бинарнике);
- распакуйте `resources\app.asar` и раздайте папку `dist` как сайт — страница
  откажется работать без main process.

## 4. Студия лицензий — выдача кодов покупателям

```bat
npm run license:studio
```

Откроется локальная страница `127.0.0.1` (только на вашем компьютере) с формой
выдачи и журналом. Студия работает **без интернета**: закрытый ключ читается
из `secrets/license-key.json` и никуда не отправляется.

### Сценарий выдачи (основной)

1. **Покупатель** запускает EXE, видит код своего компьютера (например
   `ZZG5-9ZKT`) и нажимает **«Отправить заявку владельцу»** — открывается его
   Telegram/WhatsApp/почта с готовым текстом заявки (короткий код, полный
   идентификатор, версия). Если мессенджер не открылся — покупатель нажимает
   «Скопировать заявку» или сохраняет файл `.agrorequest` и присылает его вам
   любым способом.
2. **Вы** вставляете код компьютера в студию, заполняете имя, телефон/почту и
   пометку → **«Сгенерировать код»**. Студия показывает персональный код,
   готовое сообщение покупателю и файл `.agrolic` для вложения. Запись
   автоматически попадает в журнал `secrets/ledger.csv`.
3. **Покупатель** вставляет код (или активирует файлом `.agrolic`) —
   приложение активировано навсегда. На другом компьютере этот код не
   работает: «Код выписан для другого компьютера».

Кнопки студии: «Сгенерировать код», «Скопировать код», «Скопировать текст
сообщения», «Сохранить файл .agrolic», «Отозвать» (по серийнику из журнала).
Журнал рядом с формой: дата выдачи, серийник, кому, телефон/почта, код
компьютера, тип, статус (действует/отозван) и поиск по всем полям.

**Лицензия бессрочная.** В студии нет поля «действует до» — ни в форме, ни в
коде, ни в файле лицензии. Даты встречаются только в журнале: это ваш учёт
выдачи, на работу лицензии он не влияет.

### Что умеет поле «Код компьютера»

Принимается любое разумное написание: `zzg5-9zkt`, `ZZG5 9ZKT`, с опечатками
`I/L→1`, `O→0`, а также полный 64-символьный идентификатор из заявки. Студия
сама приведёт всё к каноническому виду и откажется, если введён мусор.

### Повторная заявка и переустановка Windows

Если покупатель просит код на компьютер, которому код уже выдан, студия
**предупредит** и покажет прежнюю запись. Дальше два пути:

- покупатель переустановил Windows / сменил компьютер → нажмите
  «Продолжить»: студия перевыпустит код (новый серийник, пометка «замена» в
  журнале) и **автоматически отзовёт старый серийник** — он перестанет
  работать в следующей сборке EXE;
- похоже, покупатель раздаёт код знакомым → откажите или отзовите прежний
  серийник кнопкой «Отозвать» в журнале.

Приложение в этой же ситуации помогает покупателю само: сообщение
«Код выписан для другого компьютера» объясняет, что нужно прислать владельцу
код этого компьютера, и владелец выпустит новый ключ. Повторная активация
новым кодом проходит поверх старой лицензии — удалять файл вручную не нужно.

### Универсальный код (работает на любом компьютере)

Студия выписывает его только после явного подтверждения и помечает в журнале
как «универсальный». Используйте для особых случаев (выставка, замена
компьютера на неделю) — персональный код всегда надёжнее. Универсальные коды
v0.2.0 из `secrets\КОДЫ-АКТИВАЦИИ.txt` уже помечены в журнале как
универсальные.

## 5. Доставка кода покупателю (необязательный модуль)

Студия умеет отправлять готовое сообщение сама — СМС, Telegram-ботом или
письмом. Модуль включается переменными окружения (ключи нигде не хранятся):

| Канал | Переменные окружения |
|---|---|
| СМС через SMS.ru | `AGRO_SMS_PROVIDER=smsru`, `AGRO_SMS_API_KEY=<api_id>` (~1,7 ₽/СМС; код длинный — обычно 3–5 сегментов) |
| СМС через SMSC.ru | `AGRO_SMS_PROVIDER=smsc`, `AGRO_SMSC_LOGIN=…`, `AGRO_SMSC_PASSWORD=…` |
| Telegram-бот | `AGRO_TG_BOT_TOKEN=<токен бота>`; покупатель должен один раз написать боту `/start`, после чего у него появится chat_id |
| Почта (SMTP) | `AGRO_SMTP_HOST`, `AGRO_SMTP_PORT` (по умолчанию 587), `AGRO_SMTP_USER`, `AGRO_SMTP_PASS`, `AGRO_SMTP_FROM` (опционально) |

Пример (Windows, cmd):

```bat
set AGRO_SMS_PROVIDER=smsru
set AGRO_SMS_API_KEY=ваш-api-id
npm run license:studio
```

Отправка идёт **только из студии на вашем компьютере и только по нажатию
кнопки** — из EXE покупателя отправить ничего нельзя, там этого кода нет.
Тестовый номер для проверки доставки: **+7 960 484-34-63** (подставляется в
кнопку «Отправить СМС», если телефон покупателя не заполнен).

Ключей нет — модуль просто не включается, остальное работает.

## 6. Отзыв кода

```bat
npm run license:revoke -- 20ab3cc7ed753c65
```

или кнопка «Отозвать» в журнале студии (то же самое, но с подсказкой).

Серийник добавляется в `electron/license/keys.cjs`. Код перестаёт работать **в
следующей сборке**: приложение при каждом запуске проверяет сохранённую
лицензию заново, поэтому после обновления EXE отозванный код не пустит.
Серийник покупатель видит на экране активации и в сведениях о лицензии, а вы —
в `secrets/ledger.csv`.

## 7. Смена и добавление ключей

```bat
npm run license:keygen -- --key-id 2 --label "production-2027"
```

Новый ключ добавляется в `electron/license/keys.cjs`; приложение принимает коды
любого ключа из списка. Смысл: если закрытый ключ скомпрометирован, вы
выпускаете второй, выписываете коды им, а первый со временем убираете из
сборки. Уже выданные коды первого ключа работают, пока он в списке.

## 8. Публикация через GitHub (когда есть доступ к репозиторию)

CI собирает EXE сам на Windows-раннере и публикует его в Releases по тегу:

```bash
git push origin ветка-с-изменениями
gh pr merge --merge            # или кнопкой на сайте
git checkout main && git pull
git tag v0.2.1
git push origin v0.2.1
```

Через 5–10 минут файл появится по адресу:

```
https://github.com/Igorr112323/Weather_Cover/releases/download/v0.2.1/AgroPrognoz-0.2.1-portable.exe
```

CI делает три проверки: `verify` (179 unit-тестов + обфускация), `smoke`
(браузер: защита production-сборки, экран активации и кнопка заявки, сценарий
приложения) и `portable` (сборка EXE + `verify:package` — в том числе
проверка, что в упаковке нет закрытого ключа, журнала выдачи и контактов
владельца — **до** публикации). Закрытый ключ лицензий в CI не передаётся —
коды выписываете только вы.

⚠️ Репозиторий публичный: в нём не должно быть ни `secrets/`, ни кодов
активации. Проверить: `git status --short` не показывает `secrets/`.

## 9. Если что-то пошло не так

| Симптом | Что делать |
|---|---|
| `npm ci` падает | Node.js должен быть 20.19+; проверьте `node -v`, переустановите Node |
| Студия: «Закрытый ключ не найден» | выполните `npm run license:keygen` (один раз) и сделайте резервную копию `secrets/license-key.json` |
| Студия: «Открытый ключ key-id=N не добавлен в keys.cjs» | коды этим ключом приложение не примет: проверьте `npm run license:keys` и соберите EXE заново после keygen |
| `verify:package`: «необфусцированный core.cjs» или «кириллица в main.cjs» | сборка собрана из исходников: пересоберите `npm run dist:win` целиком, одним прогоном |
| `verify:package`: «содержимое файла не совпадает с манифестом» | между `build` и `dist:win` менялись файлы — повторите `npm run build` и `npm run dist:win` подряд |
| `verify:package`: «в файлах упаковки нет закрытого ключа» и другие «анти-слив» | что-то попало в сборку; проверьте, что не добавляли `secrets/` в `build.files` и не копировали ключ в `electron/` |
| EXE не запускается, окна нет | смотрите, не блокирует ли антивирус/SmartScreen (подписи кода нет); второй вариант — сработал shield: удалите переменные `AGRO_DEV*` и не запускайте с `--inspect` |
| «Файлы приложения изменены» у покупателя | файл подменили или сборка повреждена: выдайте новый EXE; если это повторяется массово — смотрите `docs/ЗАЩИТА.md`, раздел про целостность |
| Код не принимается | `npm run license:verify -- "<код>"`: покажет серийник, ключ и привязку. Частые причины — код отозван, код персональный и введён на другой машине, ключ в сборке другой (`npm run license:keys`) |
| Покупателю нужен код после переустановки Windows | он нажимает «Отправить заявку владельцу» на новом компьютере; вы в студии нажимаете «Продолжить» на предупреждении повторной выдачи — старый код отзовётся сам |
| СМС не доходят | проверьте баланс провайдера; студия показывает ответ SMS.ru/SMSC.ru текстом. Тест: кнопка «Отправить СМС» с номером +7 960 484-34-63 |
| Забыли, кому выдали код | журнал в студии (поиск по имени, телефону, серийнику) или `secrets/ledger.csv` |

## 10. Что усилит защиту дальше (по убыванию отдачи)

1. **Подпись кода (Authenticode, ~$200–400/год).** Убирает предупреждение
   SmartScreen и позволяет включить fuse `enableEmbeddedAsarIntegrityValidation`:
   electron-builder уже вшивает ресурс `Integrity/ElectronAsar` в EXE (видно в
   логе сборки), поэтому включение — одна строка в `package.json`. Включать
   нужно вместе с проверкой на живой машине: при несовпадении хэша Electron
   завершает приложение при запуске.
2. **Сервер активации** (один запрос при активации): мгновенный отзыв без
   перевыпуска EXE, ограничение числа машин на код, статистика утечек.
3. **Bytecode (bytenode)** для модулей лицензии: V8-байткод вместо JavaScript.
   Требует компиляции той же версией Electron и проверки на Windows.

Готовый минимум, который уже в сборке: подпись Ed25519, проверка только в main
process, токен сессии на всех каналах данных, обфускация с переименованием имён
и спрятанными строками, манифест целостности с корневыми хэшами внутри
обфусцированного стража, шесть фьюзов в бинарнике, блокировка отладчика,
DPAPI-хранилище с привязкой к компьютеру, отказ работать вне Electron,
персональные коды «один компьютер — один код» и анти-слив проверки упаковки.

# Как проверить активацию, если она у вас уже пройдена

Главная причина, по которой «проверить код активации» не получается: файл
лицензии лежит в профиле приложения —

```
%APPDATA%\AgroPrognoz\agroprognoz.license
```

— и этот файл ОДИН на все копии программы на компьютере. Поэтому вторая, третья
и свежескачанная копия `AgroPrognoz.exe` находят сохранённую лицензию и код не
просят. Так и должно быть: покупателю нельзя показывать экран активации при
каждом запуске.

Ниже — три способа проверить активацию «по-настоящему», от самого быстрого до
самого полного.

---

## 1. Быстро: сбросить активацию на своём ПК

```bat
npm run license:status      что с активацией прямо сейчас (файл, шифр, вердикт)
npm run license:reset       убрать сохранённую лицензию → приложение снова спросит код
```

`license:reset` ничего не ломает: файл лицензии переносится рядом с собой как
`agroprognoz.license.bak-20260913-101500`. Захотите вернуть как было — закройте
приложение и верните файл из копии (или введите прежний код: он всё ещё
действителен, если вы его не отзывали).

Полезные флаги: `--purge` (удалить без копии), `--dry-run` (только показать),
`--json` (для скриптов), `--instance demo` (тронуть только проверочную копию),
`--all` (включая карантины и резервные копии).

После сброса:

1. запустите `release\AgroPrognoz-0.2.1-portable.exe`;
2. на экране «Активация приложения» будет код вашего компьютера — проверьте, что
   он тот же, что показывал `npm run license:machine`;
3. вставьте код (любой годный: ваш прежний персональный или universal из
   `secrets\КОДЫ-АКТИВАЦИИ.txt`) → «Активировать».

Плохой код, чужой код и обрезанный код должны отвергаться с внятным сообщением —
это тоже часть проверки.

## 2. Не трогая свою активацию: проверочные копии

С 2026-09 копии с именем `AgroPrognoz-check-<id>.exe` живут отдельно: у них свой
файл лицензии `agroprognoz-check-<id>.license` в том же каталоге профиля. Новая
проверочная копия всегда просит код — даже на компьютере, где основная уже
активирована. Ваша активация и ваши данные при этом не трогаются вообще.

Три способа включить такой режим (см. `electron/license/checkmode.cjs`):

| Что сделать | Результат |
|---|---|
| переименовать EXE в `AgroPrognoz-check-demo.exe` | лицензия в `agroprognoz-check-demo.license` |
| запустить с `--check-instance=demo` | то же самое, имя файла можно не менять |
| задать `AGRO_CHECK_INSTANCE=demo` | то же самое, удобно в скриптах и в CI |

Порядок приоритета: переключатель → переменная окружения → имя файла.

```bat
copy release\AgroPrognoz-0.2.1-portable.exe release\AgroPrognoz-check-demo.exe
release\AgroPrognoz-check-demo.exe        :: спросит код
```

Что важно: проверочный режим меняет **только имя файла лицензии**. Подпись кода,
привязка к компьютеру, список отзыва, проверка целостности файлов и отказ
работать вне Electron остаются такими же. Обойти активацию этим режимом нельзя —
им можно только заставить приложение честно спросить код.

## 3. Полностью: самопроверка механизма активации

```bat
npm run activation:selftest
```

Прогоняет весь сценарий на настоящем страже (`electron/license/guard.cjs`), во
временном каталоге и с выдуманным ключом — боевые `secrets/` и ваши активации не
затрагиваются. 21 проверка:

```
✔ без файла лицензии приложение требует код активации
✔ данные до активации закрыты
✔ универсальный код принят
✔ срок действия не ограничен
✔ файл лицензии создан
✔ после перезапуска остаётся активированным
✔ персональный код этого компьютера принят
✔ персональный код на другом компьютере отклонён        — MACHINE_MISMATCH
✔ скопированный файл лицензии чужим компьютером не принимается — MACHINE
✔ подменённый файл лицензии уходит в карантин и требует код  — MAC
✔ свежая проверочная копия требует код, хотя основная активирована
✔ отозванный серийник не активирует приложение            — REVOKED
✔ выдуманный код отклонён                                 — SIGNATURE
...
✔ Пройдено проверок: 21
```

Эта же проверка встроена в `npm run harden` (страж самопроверяется на
обфусцированном коде) и в `npm test` (`tests/activation-doctor.test.mjs`).

## 4. Проверить, что код покупателя действительно его

```bat
npm run license:machine                          код ЭТОГО компьютера
npm run license:issue -- --bind ZZG5-9ZKT        код для конкретного компьютера
npm run license:verify -- "<код>" --machine ZZG5-9ZKT
```

## 5. Станция «Активация ключей» — ссылка, выдача кодов и готовый EXE

Каталог [`station/`](../station) — это отдельная веб-станция (её можно вынести в
отдельный репозиторий «Активация ключей»): вставили то, что прислал
пользователь → получили персональный код, готовое сообщение, файл `.agrolic` и
**ссылку на скачивание проверочного EXE**, который при открытии запросит ключ.

```bat
npm run station                    :: ссылка появится в консоли, браузер откроется сам
npm run station -- --exe release   :: из чего делать проверочную копию
npm run station:export             :: выгрузить станцию в ../agro-activation-keys (готово к git init)
```

### 5.1. Совсем без Node: один файл, двойной щелчок

[`station/standalone/aktivaciya-klyuchey.html`](../station/standalone/aktivaciya-klyuchey.html) —
вся выдача в одном HTML-файле: скачайте его (или возьмите из репозитория),
откройте двойным щелчком, на вкладке «Ключи» вставьте содержимое
`secrets/license-key.json`, дальше вставьте в поле заявки текст покупателя →
получите код, сообщение покупателю, CSV журнала и ссылку на EXE.

- Сеть странице не нужна: она ничего никуда не отправляет, закрытый ключ живёт в
  `localStorage` этого браузера (кнопка «Забыть» на вкладке «Ключи» удаляет её).
- Формат кода в файл вставляется дословно из `electron/license/core.cjs` —
  собирает его `npm run station:standalone`, а тест `station/tests/standalone.test.mjs`
  сверяет вердикты страницы с приложением. Правки в `electron/license/*` →
  `npm run station:sync && npm run station:standalone`.
- Нужен браузер со Ed25519 в WebCrypto: Chrome/Edge 137+, Firefox 130+, Safari 17+.

Подробности — в [`station/README.md`](../station/README.md).

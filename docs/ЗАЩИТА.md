# Защита приложения

Документ для владельца приложения: что именно мешает разборке и подмене сборки
и где проходят честные границы этой защиты.

Кода активации в приложении нет: оно запускается сразу и ничего не спрашивает.
Всё, что описано ниже, — про защиту самой сборки, а не про доступ к функциям.

---

## 1. Что видит человек

1. Запуск `AgroPrognoz.exe` → заставка → интерфейс приложения.
2. Никаких кодов, заявок и сроков: данных о лицензии в приложении нет.

## 2. Слои защиты

### 2.1 Данные отдаёт main process, а не интерфейс

Renderer работает в sandbox'е (`contextIsolation: true`, `nodeIntegration: false`)
и получает из preload только узкий набор операций: чтение/запись базы,
сохранение копии повреждённой базы, запись файла выгрузки и два односторонних
сигнала. Файловую систему renderer не видит вовсе, а каждый IPC-канал доступен
только главному окну (`event.sender === mainWindow.webContents`) — содержимое,
открытое через `window.open`, до данных не дотянется.

### 2.2 Обфускация main process

В сборку уходит не `electron/`, а `hardened/electron/` — обфусцированная копия
(`javascript-obfuscator`):

- `shield.cjs` (условия запуска и защита от отладки): перемешивание потока
  управления, мёртвый код, строки в base64-массиве с ротацией и сдвигом
  индексов, разбиение строк, выражения вместо чисел, экранирование кириллицы,
  `selfDefending` — код ломается при попытке привести его к читаемому виду;
- `main.cjs` / `persistence.cjs`: тот же набор мягче (без `selfDefending` —
  надёжность запуска важнее), но со 100%-ным переносом строк в массив,
  экранированием кириллицы и переименованием имён верхнего уровня
  (`renameGlobals`): ни «АгроПрогноз — Кукуруза», ни `createSplashWindow` в
  бинарнике не остаются;
- `preload.cjs`: щадящий профиль — он работает в sandbox без Node-API.

Обфускация детерминирована (seed от версии и имени файла): одна и та же сборка
даёт байт в байт тот же результат.

### 2.3 Electron Fuses (защита в самом бинарнике)

В `package.json → build.electronFuses`, применяются electron-builder'ом к
`AgroPrognoz.exe`. Это не JavaScript — правкой кода приложения не обходится:

| Fuse | Значение | Что закрывает |
|---|---|---|
| `runAsNode` | **выкл** | `ELECTRON_RUN_AS_NODE=1` → Node REPL с правами процесса |
| `enableNodeOptionsEnvironmentVariable` | **выкл** | `NODE_OPTIONS=--require ./patch.js` |
| `enableNodeCliInspectArguments` | **выкл** | `--inspect`, `--inspect-brk`, SIGUSR1 |
| `onlyLoadAppFromAsar` | **вкл** | подмена кода каталогом `app/` рядом с EXE |
| `enableCookieEncryption` | **вкл** | cookie-хранилище в открытом виде |
| `grantFileProtocolExtraPrivileges` | **выкл** | лишние привилегии `file://` |

Вторым слоем при запуске `electron/shield.cjs` проверяет условия:
подключённый инспектор, отладочные переключатели (`--inspect`,
`--remote-debugging-port`, `--js-flags`, `--disable-web-security`), переменные
разработки (`AGRO_DEV*`) и запуск не из упаковки без исходников. В упакованном
приложении инструменты разработчика выключены (`devTools: false`), а повторная
попытка их открыть завершает процесс.

### 2.4 Вне Electron приложение не работает

Production-сборка, открытая как обычная страница (например, кто-то распаковал
`app.asar` и раздаёт `dist/` статикой), показывает отказ: моста `window.agro`
нет, а данные и работа с файлами живут в основном процессе. Ветка «режим
разработки» в production-бандле вырезана статически
(`import.meta.env.DEV` → `false`), поэтому включить её в готовой сборке нельзя.
Проверяется в CI тестом `npm run test:gate`.

### 2.5 Мелочи, которые тоже работают

- `asar: true`, `asarUnpack` убран — `dist/` лежит внутри архива, а не рядом;
- из упаковки исключены исходники `calculations/`, `src/`, `scripts/`, `tests/`
  и `node_modules/`;
- IPC-каналы доступны только главному окну;
- путь для выгрузки выбирает человек в системном диалоге — renderer передаёт
  только имя файла и содержимое;
- разрешения (геолокация, камера, уведомления, буфер обмена) отклоняются;
- навигация и `window.open` запрещены, внешние ссылки открываются только из
  allowlist атрибуции источников карт.

## 3. Честные границы

Офлайн-приложение нельзя сделать невзламываемым: у человека с исполняемым
файлом и достаточным временем всегда есть теоретическая возможность его
пропатчить. Что здесь реально:

- нельзя запустить приложение как Node или подключить к нему отладчик — фьюзы
  и `shield.cjs`;
- нельзя подменить код каталогом рядом с EXE — `onlyLoadAppFromAsar`;
- нельзя получить данные правкой интерфейса — их отдаёт только main process;
- нельзя прочитать исходники main process «в лоб» — в упаковке obfuscated-копия
  без русских строк и знакомых имён.

Что остаётся на стороне человека с навыками реверса: дизассемблирование
обфусцированного main process и ручная правка внутри перепакованного
`app.asar`. Это часы работы и пересборка под каждую версию.

**Что усилит защиту сильнее всего остального (требует вложений):**

1. **Подпись кода** (сертификат Authenticode, ~$200–400/год). Даёт SmartScreen-
   репутацию и, главное, позволяет включить fuse
   `enableEmbeddedAsarIntegrityValidation`: тогда `app.asar` проверяется самим
   Electron до запуска JavaScript. Сейчас этот fuse намеренно **не включён**:
   на Windows он требует вшить в EXE ресурс `Integrity/ElectronAsar` с хэшем
   заголовка архива, а без него приложение не запустится вовсе. Включать можно
   только вместе с вшиванием ресурса и проверкой на живой машине.
2. **Bytecode (bytenode)** для `main.cjs` и `shield.cjs`: V8-байткод вместо
   JavaScript. Требует компиляции той же версией Electron, что и сборка, и
   проверки на Windows.

## 4. Как это проверяется

| Проверка | Где |
|---|---|
| 64 unit-теста: календарные периоды, валидация, детерминированность движка, CRUD сортов, миграции, отчёты, CSV | `npm test` |
| Обфускация не сломала код: синтаксис каждого файла, решения обфусцированного `shield.cjs` (чистый запуск, `--inspect`, отладочный порт, переменные разработки, распакованная копия), загрузка обфусцированного preload с подставным `electron` (мост `window.agro` цел, мусор на вводе отклонён) | `npm run harden` (самопроверка, 19 проверок) |
| Production-сборка в браузере отказывается работать | `npm run test:gate` (CI, job `smoke`) |
| Состав `app.asar` (нет исходников, скриптов, тестов, `node_modules`) и состояние фьюзов в `AgroPrognoz.exe` | `npm run verify:package` (CI, job `portable`, до публикации артефакта) |

`npm run harden` и `npm run verify:package` можно запускать и локально — они не
требуют Windows (проверяется содержимое сборки, а не запуск EXE).

## 5. Порядок сборки релиза

```bash
npm ci
npm run icon && npm run prepare:assets
npm test
npm run build          # dist/
npm run dist:win       # patch-portable-nsi → harden → electron-builder
npm run verify:package # разбор release/win-unpacked: asar, фьюзы
```

CI делает то же самое в job `portable` и публикует
`AgroPrognoz-<version>-portable.exe`.

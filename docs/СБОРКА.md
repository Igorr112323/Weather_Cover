# Сборка Windows EXE

Как собирается `AgroPrognoz-<version>-portable.exe`, что происходит на каждом
шаге и что делать, если проверка не проходит. Про защиту и лицензию —
[`docs/ЗАЩИТА.md`](ЗАЩИТА.md).

## Требования

- Node.js 20+ и npm (сборка идёт на Node; Windows нужен только для
  `dist:win` — electron-builder собирает portable EXE под Windows).
- Доступ в интернет для `npm ci` (Electron, electron-builder, Playwright).

## Конвейер

```bash
npm ci                        # установка (включая Electron, electron-builder, Playwright)
npm run icon                  # build/icon.png — из исходного изображения (ImageMagick)
npm run prepare:assets        # data/weather.sqlite, public/demo-*.csv, public/tiles.json
npm test                      # 179 unit-тестов, включая лицензию и студию выдачи
npm run build                 # Vite → dist/ (production, ветка DEV вырезана)
npm run dist:win              # три шага: NSIS-шаблон → harden → electron-builder
npm run verify:package        # разбор release/win-unpacked: asar, целостность, фьюзы
```

`npm run dist:win` внутри:

1. `scripts/patch-portable-nsi.mjs` — правит шаблон portable-установщика
   electron-builder в `node_modules`, чтобы заставка держалась до первого окна
   приложения (правка идемпотентна: повторный запуск ничего не ломает).
2. `npm run harden` — `scripts/harden.mjs`: обфускация `electron/` →
   `hardened/electron/`, манифест SHA-256 → `electron/license/integrity-data.cjs`,
   затем **самопроверка** (56 проверок): обфусцированные модули грузятся,
   синтаксис каждого файла корректен, цепочка хэшей сходится, порча файла и
   подмена манифеста ловятся, полный цикл активации заканчивается выдачей
   токена, обфусцированный `preload.cjs` грузится с подставным `electron` и
   отдаёт мост `window.agro` целиком (токен сессии наружу не уходит),
   в `hardened/electron/` нет приватных ключей.
3. `electron-builder --win portable` — упаковка в `release/`.

## Что кладётся в EXE

`build.files` в `package.json` — явный список с переносом путей:

| Источник | Куда в `resources/app.asar` | Зачем |
|---|---|---|
| `dist/` | `dist/` | интерфейс (production-сборка Vite) |
| `hardened/electron/` | `electron/` | обфусцированный main process; исходники `electron/` в EXE не попадают |
| `build/icon.png` | `build/icon.png` | иконка окна из кода |
| `package.json` | `package.json` | `main`, `productName`, версия |

Не упаковывается: `node_modules/` (в рантайме не нужны), `calculations/`
(исходники расчётов — в бандле `dist/`), `data/` (база создаётся у
пользователя), `secrets/` (закрытый ключ лицензий), исходники `electron/`,
`tests/`, `scripts/`, `hardened/electron/license/integrity-data.cjs` не
подменяется ничем — он и есть манифест.

`asarUnpack` пуст: весь код внутри `app.asar`. Обработчик `app://` читает файлы
через `fs` (архив прозрачен), WASM подключается через `?url`.

### Почему `dependencies` в `package.json` пуст

electron-builder **всегда** кладёт в `app.asar` production-зависимости из
`dependencies`, независимо от `build.files`. В этом приложении они не нужны в
упаковке:

- интерфейс собирает Vite — шрифты Inter, `chart.js`, `leaflet` и
  `sql-wasm-browser.wasm` лежат в `dist/assets/`;
- main process требует только `electron` (встроен в бинарник).

Поэтому `@fontsource/inter`, `chart.js`, `leaflet` и `sql.js` стоят в
`devDependencies`: они нужны для сборки, но в EXE не едут. Это минус десятки
мегабайт и минус необфусцированный код в архиве. `npm run verify:package`
проверяет, что `node_modules/` в `app.asar` не появился, — если кто-то вернёт
пакет в `dependencies`, проверка упадёт.

Инструменты сборки (`electron-builder`, `vite`, `sharp`, `playwright`,
`javascript-obfuscator`) — тоже `devDependencies`, как и положено.

## Electron Fuses

`build.electronFuses` в `package.json` применяется electron-builder'ом к готовому
`AgroPrognoz.exe`:

```json
{
  "runAsNode": false,
  "enableCookieEncryption": true,
  "enableNodeOptionsEnvironmentVariable": false,
  "enableNodeCliInspectArguments": false,
  "onlyLoadAppFromAsar": true,
  "loadBrowserProcessSpecificV8Snapshot": false,
  "grantFileProtocolExtraPrivileges": false
}
```

`enableEmbeddedAsarIntegrityValidation` **не включён намеренно**: на Windows он
требует ресурс `Integrity/ElectronAsar` в PE-файле (electron-builder его не
создаёт), и без ресурса приложение завершается при запуске. Включать можно
только вместе с вшиванием ресурса и проверкой на живой машине.

Проверить фьюзы готовой сборки: `npm run verify:package` (читает fuse-wire из
EXE и сверяет с ожидаемым состоянием).

## Проверка собранного приложения

`npm run verify:package` — обязательный шаг перед публикацией (в CI он идёт до
загрузки артефакта):

1. **Состав `app.asar`**: есть `package.json`, `electron/main.cjs`,
   `dist/index.html`; нет `node_modules`, `calculations`, исходников
   `electron/` и приватных ключей.
2. **Обфускация**: `electron/license/core.cjs` в упаковке содержит маркеры
   `javascript-obfuscator` и массив строк, но не содержит исходных сигнатур;
   в `main.cjs`, `preload.cjs`, `persistence.cjs` и `guard.cjs` не осталось
   ни кириллицы, ни исходных имён функций.
3. **Целостность упакованных файлов**: байты внутри `app.asar` пересчитываются и
   сверяются с манифестом; отдельная проверка цепочки корневых хэшей.
4. **Страж из упаковки**: грузится `hardened`-версия `guard.cjs` с
   подготовленным окружением и проверяет настоящий код на вшитых хэшах,
   поддельный код и порчу файла.
5. **Фьюзы**: `getCurrentFuseWire` читает состояние из `AgroPrognoz-*.exe` и
   сверяет с `build.electronFuses`.

## CI

`.github/workflows/windows-build.yml`, три независимых job'а:

| Job | Что делает | Нужно для публикации |
|---|---|---|
| `verify` | `npm ci`, иконка, ассеты, `npm test`, `npm run build`, `npm run harden` | да |
| `smoke` | сборка → Playwright: production-бандл в браузере должен отказать (`test:gate`), затем экран активации (`test:activation`) и сценарий приложения на dev-сервере (`test:smoke`), скриншоты артефактом | нет |
| `portable` | сборка → `dist:win` → `verify:package` → артефакт `AgroPrognoz-<version>-portable`, при теге `v*` — GitHub Release | да |

## Релиз

```bash
# 1. версия (совпадает с тегом)
npm version 0.2.1 --no-git-tag-version
# 2. коммит, тег, публикация
git add -A && git commit -m "release: 0.2.1"
git tag v0.2.1 && git push origin main --tags
```

CI соберёт EXE и создаст релиз; ссылка на скачивание:

```
https://github.com/Igorr112323/Weather_Cover/releases/download/v0.2.1/AgroPrognoz-0.2.1-portable.exe
```

Закрытый ключ лицензий в CI не передаётся: сборка проверяется выдуманными
кодами. Настоящие коды выписывает владелец локально (`npm run license:issue`).

## Если что-то пошло не так

| Симптом | Причина и действие |
|---|---|
| `verify:package`: «не найден resources/app.asar» | `dist:win` не завершился; смотреть лог electron-builder |
| «необфусцированный core.cjs внутри app.asar» | `harden` не отработал или `build.files` отдаёт `electron/` вместо `hardened/electron/` |
| «содержимое packaged-файла не совпадает с манифестом» | сборка собрана из другого `dist/`: пересобрать `build` → `harden` → `dist:win` одним прогоном |
| «fuse … должен быть выключен» | electron-builder не применил фьюзы: проверить `build.electronFuses` в `package.json` и версию electron-builder |
| Приложение не запускается после сборки | смотреть `electron/license/shield.cjs` — он блокирует запуск при подключённом отладчике и отладочных переключателях; в логе будет `SHIELD:` |
| `harden` падает на самопроверке | обфускация сломала конкретный модуль: в `scripts/harden.mjs` есть профили, уменьшите агрессивность для проблемного файла и пересоберите |
